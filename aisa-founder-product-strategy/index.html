AIsa / PRODUCT PERSPECTIVE02 / 开发者体验

Skill、CLI、云端 API 职责不够直观

2 一个示例：从接入走到预期结果

AIsa / PRODUCT PERSPECTIVE04 / 供应商质量

HTTP 200 之后，结果真的有用吗？

判断层级关键问题选择证据
供应商来源与使用条件是否可信？主体、授权、使用限制、故障处理
接口能否稳定执行？成功率、延迟、超时、版本稳定性
任务结果返回结果是否可用？完整性、相关性、新鲜度、可追溯性
准入测试
→
小规模调用
→
验收与推荐
→
隔离 / 复测 / 退出

先过滤能力与使用条件，再比较质量、延迟和单位成功任务总成本；计入重试与二次验证。

建议从重点任务建立质量记录；新供应商保留测试机会，商业推广与质量排序分开。06 / 09
AIsa / PRODUCT PERSPECTIVE优先行动

先做通一条路径，再扩大供给与分发

1

聚焦一个任务入口

同一类客户
同一个首页主张
同一个可运行示例

2

接入发现与选择

一个重点能力类目
少量候选与选择理由
明确预算和替代边界

3

记录质量并反馈

结果验收与成本追踪
失败隔离与复测
据证据更新推荐

不优先增加平行入口，也不一开始覆盖全目录自动路由。
以重复付费和贡献毛利检验这条路径是否真正成立。
希望结合实际客户、调用与留存数据，进一步验证判断并推进产品改进。07 / 09
